# 성동구 5m(approach2) vs 1mtrue(진짜 1m DEM, 9타일) 비교 결과

## ⚠️ 핵심 경고 — 이 비교는 "해상도 효과" 검증으로 쓸 수 없음

**결론부터: 이 문서의 비교 수치는 서울 v2-vs-v3 비교(`2026-07-20_v2v3_해상도비교_결과.md`)와
성격이 다르다.** v2-vs-v3는 "동일한 현재 파이프라인, DEM 소스만 다름"이라는 깨끗한 비교였지만,
이번 비교 대상인 `solweig_approach2_5m`은 **2026-07-11~12에 만들어진 구버전 파이프라인
산출물**이다(`configsolweig.ini` 수정일 확인). 그 이후 이 프로젝트에서 있었던 주요 방법론
변경(2026-07-16 UTCI 직접 채택 전환, 단일 기상값 구조 확정, UMEP `Tgmaps_v1.py` 버그 수정
등, `CLAUDE.md`·`project_status` 메모리 참고)이 approach2_5m에는 반영되지 않았을 가능성이
높다. 실제로 특정 링크 좌표를 1m 원본 픽셀과 직접 대조한 결과, 같은 시각(13시) 같은 지점에서
5m 링크값 58.4°C 대 1m 원본 픽셀 45~49°C로 **10°C 이상 차이가 실측 확인됨** — 이는 해상도
차이로 설명하기엔 너무 크고, 픽셀 단위 전체 비교(r=0.86)와도 규모가 안 맞는다.

**즉 아래 수치는 "성동구에서 5m와 1m 해상도가 결과에 어떤 영향을 주는가"에 대한 답이 아니라,
"오래된 파이프라인과 현재 파이프라인이 다르다"는 것을 보여줄 뿐이다.** 논문에 해상도 강건성
근거로 이 결과를 쓰면 안 된다. 진짜 해상도 비교가 필요하면 approach2_5m을 **현재 파이프라인
스크립트로 재실행**하거나(가장 확실), 서울 v2-vs-v3처럼 이미 방법론이 통일된 비교로 대체해야
한다.

## 1. 목적(원래 의도, 위 경고로 인해 미달성)

성동구 스케일에서 5m 격자와 1m 격자(진짜 1m DEM, 9분할 타일링) 결과를 비교해 해상도 강건성을
추가 검증하려 했음.

## 3. 결과 — 픽셀 단위(1m→5m 평균 리샘플 후 비교)

| 지표 | Tmrt 평균 | UTCI 평균 |
|---|---|---|
| MAE | 1.219°C | 0.271°C |
| RMSE | 2.697°C | 0.601°C |
| 상관계수 r | 0.8576 | 0.8573 |
| Hard Cut(38°C) 일치율 | - | 94.07% |

시간대별 r은 0.858~0.966으로 비교적 준수하나(상세: `03_Method_C/results/
compare_5m_1mtrue_seongdong/2026-07-28_hourly_stats_5m_vs_1mtrue.csv`), 서울 v2-vs-v3의
r=0.9964·Hard Cut 일치율 99.68%에 비하면 명백히 낮다 — 위 경고에서 설명한 파이프라인
버전 차이가 원인일 가능성이 높다.

## 4. 결과 — 링크 단위(469,010개 중 성동구 16,316개 링크, 5m 버퍼 zonal mean)

| 지표 | Tmrt | UTCI |
|---|---|---|
| MAE | 13.146°C | 3.058°C |
| RMSE | 13.846°C | 3.208°C |
| 상관계수 r | 0.5338 | 0.5360 |
| Hard Cut(38°C) 일치율 | - | **22.05%**(불일치 12,719/16,316) |

**Hard Cut 일치율 22%는 무작위(50%)보다도 낮다 — 이 자체가 "정상적인 해상도 차이"로는 설명
불가능한 이상치이며, 위 경고의 근거다.** 픽셀 단위(94%)와 링크 단위(22%)의 극단적 괴리도
파이프라인 버전 차이가 공간적으로 불균등하게(예: 도로 위주로) 나타났을 가능성을 시사하나,
정확한 원인은 이 문서에서 규명하지 않았다(⚠️ 추가 조사 필요).

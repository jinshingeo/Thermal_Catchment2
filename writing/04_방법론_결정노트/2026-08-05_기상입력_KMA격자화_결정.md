## 결정

서울 전역 met profile(`04_MeteoComparison/code/02_build_seoul_met_profile.py`)의
**기온(Ta)·습도(RH)·풍속**을 기존 S-DoT 단순평균/AWS 단일 관측소(421) 균일값에서
**기상청 API 허브 500m 격자 분석자료**로 교체한다. **일사량(Kdown)은 교체하지 않고
기존 방식을 유지**한다.

## 데이터 출처

### 신규 — 기온/습도/풍속
- 사이트: 기상청 API 허브 (https://apihub.kma.go.kr)
- API: "융합기상 > 고해상도 격자자료"(seqApi=971), 활용신청 승인 2026-08-05
- 요청 URL: `https://apihub.kma.go.kr/api/typ01/cgi-bin/url/nph-sfc_obs_nc_api?obs={ta|hm|ws_10m}&tm={YYYYMMDDHHmm}&disp=A&authKey={key}`
- 인증키: `.env`(gitignore 처리)에 보관, 저장소에 커밋하지 않음
- 응답 사양(테스트 확인, 2026-08-05): 전국 2049×2049 격자, 콤마구분 ASCII, 500m 해상도,
  결측/영역외 `-999.0`. 좌표 헤더 없음 → grid index↔lon/lat 매핑은 별도
  "격자자료 위경도 API"(1.6번)에서 1회만 받아 재사용
- 다운로드 범위: 2025-07-23~2025-08-03(폭염일 12일) × 06~19시 매정시(14개 시각)
  = 168 timestamp × 3 요소(ta/hm/ws_10m) = 504회 호출 예정

### 유지 — 일사량
- 출처: 기상자료개방포털(data.kma.go.kr) ASOS 108(서울) 시간자료,
  `data/OBS_ASOS_TIM_20260702021244.csv`(2026-07-02 다운로드)
- 처리: GHI(W/m²) 환산 후 Erbs et al.(1982) 직산분리모델로 직달/확산 분리 (기존과 동일)
- 사유: ASOS 관측소가 서울 내엔 사실상 108 하나뿐이라, 인접 ASOS(인천/수원/파주 등
  20~50km 이격)로 IDW해도 실질적 해상도 개선이 아니라 외곽점 왜곡 위험이 큼.
  Ta/RH/풍속(500m 촘촘한 융합격자)과 근거의 질이 다름 — "관측망이 촘촘한 변수만
  보간했다"는 서술이 방법론적으로 더 방어 가능.

## 07-16 문서와의 관계 (⚠️ 명시적 재검토 필요)

`2026-07-16_방법론_단일기상값_MRT공간화_근거.md`는 Ta/RH/풍속을 **단일값으로 유지해야
한다**는 결론을 Bröde(2012)·Brecht(2020)·Lee(2025)·Basu(2024)·Colaninno(2024) 등
8편 인용으로 뒷받침한 문서다. 이번 결정은 그 결론을 부분적으로 뒤집는다. 아래는 두
문서의 논거가 실제로 충돌하는지 항목별로 재검토한 것 — **최종 판단은 아니며, 서론/
방법론 집필 전 지도교수 확인 필요**:

| 07-16 논거 | 오늘 결정과의 관계 |
|---|---|
| 2-5, 2-6절: UTCI는 "동(city quarter) 단위 이상" 스케일에 맞게 설계, 건물해상도(URock, 1.1m) 풍속은 스케일 부정합 | **충돌 아닐 가능성** — KMA 500m 격자는 건물해상도 CFD가 아니라 관측망 융합 분석격자. Brecht(2020)가 말하는 "city quarter" 스케일에 오히려 더 가까움(07-16 문서 2-7절이 대안으로 제시한 TARGET 100m격자보다도 coarse함) |
| 1-3절: 풍속만 고비용 정밀화하면 Axis 1(비용 대비 효율) 논지와 모순 | **충돌 아닐 가능성 낮음** — KMA API는 URock류 물리모델이 아니라 데이터 다운로드라 계산비용 자체가 낮음. 다만 "MRT는 저비용 방식을 택하면서 기상은 격자자료로 정밀화"하는 게 일관성 있는 서사인지는 Discussion에서 명시적으로 설명 필요 |
| 1-5절: 단일값이 Axis 2(단일값/IDW/MQ/크리깅 비교)의 필수 기준선(baseline) | **직접 충돌** — Axis 2 비교의 "단일값" arm을 이번 결정 이후에도 유지할지 결정 필요. (안 1) 단일값 arm은 비교용으로 남기고 KMA 격자는 "채택 방식"으로 별도 제시 (안 2) Axis 2를 "단일값 vs KMA격자" 비교로 재정의 |
| 1-6절: 타임라인상 이미 끝난 파이프라인 재구축은 비현실적 | **가장 직접적인 긴장** — 2026-07-16 대비 SCI 투고까지 남은 시간이 더 줄어든 상태(2026-08-05 기준). 이번 결정의 실제 시간비용을 과소평가하지 말 것 |

**잠정 결론(2026-08-05)**: 사용자 지시로 진행. 위 표의 "직접 충돌" 두 항목(Axis 2 기준선,
타임라인)은 실제 파이프라인 구축·검증 완료 후 재확인 필요. 07-16 문서는 삭제하지 않고
